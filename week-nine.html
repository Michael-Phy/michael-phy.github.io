Networking & Cloud‑based IoT Control

Project Overview

This week I explored IoT networking using ESP32‑C3 combined with Firebase Realtime Database. The goal is to achieve cloud‑remote hardware control: send commands from a web client over the internet, store status inside the cloud database, and let the microcontroller continuously read database values to toggle physical hardware outputs. This establishes a bidirectional internet‑connected workflow for my physical‑computing prototype.

System Workflow

  1. ESP32‑C3 connects to local Wi‑Fi, then authenticates and connects to Firebase Realtime Database.
  2. The microcontroller repeatedly fetches the /LED_STATUS string value stored on cloud server every one second.
  3. A web frontend sends ON or OFF commands and writes those strings into Firebase database.
  4. When ESP32 reads ON, it turns on the on‑board LED; reading OFF switches the LED off.

Arduino Firmware (ESP32‑C3)

#include <WiFi.h>                                 // esp32 library
#include <FirebaseESP32.h>                        // firebase library

#define FIREBASE_HOST "https://acontroller-aadb8-default-rtdb.europe-west1.firebasedatabase.app/"
#define FIREBASE_AUTH "cAdMvfIBB8BVwihI1A19RnIe37LriNSuFVNClYgs"
#define WIFI_SSID "my_ssid"
#define WIFI_PASSWORD "my_password"

String fireString = "";
int ledpin = 13;

FirebaseData firebaseData;

void setup() {
  Serial.begin(115200);
  delay(1000);
  pinMode(ledpin, OUTPUT);
  WiFi.begin(WIFI_SSID, WIFI_PASSWORD);

  Serial.print("Connecting to ");
  Serial.print(WIFI_SSID);
  while (WiFi.status() != WL_CONNECTED) {
    Serial.print(".");
    delay(500);
  }

  Serial.println();
  Serial.print("Connected to ");
  Serial.println(WIFI_SSID);
  Serial.print("IP Address is : ");
  Serial.println(WiFi.localIP());
  Firebase.begin(FIREBASE_HOST, FIREBASE_AUTH);
  Firebase.reconnectWiFi(true);
  Firebase.set(firebaseData, "/LED_STATUS", "OFF");
}

void loop() {
  Firebase.get(firebaseData, "/LED_STATUS");
  fireString = firebaseData.stringData();
  Serial.println(fireString);
  
  if (fireString == "ON") {
    Serial.println("Led Turned ON");
    digitalWrite(ledpin, HIGH);
  }
  else if (fireString == "OFF") {
    Serial.println("Led Turned OFF");
    digitalWrite(ledpin, LOW);
  }
  else {
    Serial.println("Please send ON/OFF");
  }
  delay(1000);
}

Important note: Before upload, you must replace WIFI_SSID and WIFI_PASSWORD with your actual Wi‑Fi credentials. The Firebase host and auth key are copied directly from your Firebase project console.

Key Technical Challenges & Observations

  • Wi‑Fi reconnection handling: When local network drops, Firebase.reconnectWiFi(true) allows ESP32 to automatically rebuild connection after Wi‑Fi resumes.
  • Database security rules: Read‑write permission must be configured properly in Firebase console, otherwise ESP32 cannot pull or push database entries.
  • Data type matching: The firmware reads string‑type value. Mismatched data type (e.g. boolean / integer stored in database) will cause unexpected hardware behaviour.
  • Latency: There is small network delay between web button press and LED reaction, caused by cloud database round‑trip communication.
